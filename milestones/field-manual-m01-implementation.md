# Field Manual — Milestone 1 Implementation Packet

## Goal

Replace the starter Android Compose screen with a local, static,
scrollable Field Manual library.

The application launches directly to a list of hard-coded demo
`ManualDocument` entries. This milestone establishes a visible,
offline local-library interface only.

## Package layout

```text
app/src/main/java/<your-package>/
  MainActivity.kt
  data/
    ManualDocument.kt
    SampleManualDocuments.kt
  ui/
    ManualLibraryScreen.kt
    ManualDocumentList.kt
    ManualDocumentItem.kt
```

`<your-package>` means the package already generated by Android Studio.
Do not invent a second package root.

## Responsibilities

### MainActivity.kt

- Android application entry point.
- Calls `setContent`.
- Applies the generated application theme.
- Renders `ManualLibraryScreen`.
- Contains no sample data and no list-item UI.

### data/ManualDocument.kt

- Defines the in-memory document model.
- Contains no Compose or Android framework code.

```kotlin
data class ManualDocument(
    val id: String,
    val title: String,
    val tags: List<String>,
    val source: String,
)
```

### data/SampleManualDocuments.kt

- Defines at least five local demonstration documents.
- Uses clearly fictional or explicitly demo-only source labels.
- Does not claim that medical, legal, emergency, or safety information
  was verified.

### ui/ManualLibraryScreen.kt

- Defines the app's first and only screen.
- Uses `Scaffold` with a top app bar titled `Field Manual`.
- Passes sample documents to `ManualDocumentList`.
- Does not add navigation, file import, networking, or persistence.

### ui/ManualDocumentList.kt

- Receives `List<ManualDocument>`.
- Uses `LazyColumn`.
- Supplies stable document keys based on `id`.
- Delegates each list entry to `ManualDocumentItem`.

### ui/ManualDocumentItem.kt

- Renders one document as a Material 3 `Card`.
- Displays title, source, and tags.
- Has no click behavior in Milestone 1.

## Explicit exclusions

- Detail screen and navigation
- Search or filtering
- Bookmark actions
- File import
- Full document bodies
- Database or Room
- Persistent state
- Networking and cloud sync
- RSS
- PDF or Markdown rendering
- AI features
- Emergency alerts or professional guidance claims

## Acceptance criteria

1. The project builds successfully in Android Studio.
2. The application launches directly to the Field Manual library screen.
3. At least five hard-coded demonstration documents render.
4. Each card shows a title, source, and tags.
5. The list scrolls vertically.
6. The interface remains readable on a phone-sized emulator or device.
7. The app makes no network request and uses no storage permission.
8. The finished behavior is tested manually and committed to Git.

## Manual test checklist

- Launch the app from Android Studio.
- Confirm the top bar says `Field Manual`.
- Confirm at least five document cards appear.
- Confirm each card has a readable title, source, and tag row/wrap.
- Scroll to the final card.
- Rotate the emulator or test a narrower/wider screen if convenient.
- Confirm the app does not crash.
- Confirm no permission dialog or account prompt appears.
